# DSH 自定义登录：实现方案与踩坑

> `deepseek-harness-login` 的实现笔记：账户链路怎么走、方案怎么落地、踩过哪些坑。
> 适用 DSH 桌面版（`DeepSeek Harness.exe`），插件 v0.4.4。

---

## 1. 背景

DSH 默认用 DeepSeek 账号（OAuth 浏览器回调）登录。目标场景是**内网 / 离线部署**，
客户环境访问不了 `platform.deepseek.com`，要换成自己的账户体系。

| 验收项 | 要求 |
|---|---|
| 登录方式 | 用户名 + 密码，不连外网 |
| 快速验证 | `dawei` / `123456` |
| 登录后 | 能进工作区，账户信息是自己的内容 |
| 界面 | 不出现 DeepSeek 平台入口 |
| 实现 | 插件形式，不改 DSH 源码 |

---

## 2. 先看懂账户链路

### 2.1 三层结构

| 层 | 包 | 作用 |
|---|---|---|
| 凭证存储 | `dsh-credentials` + `credentials-local` | 读写 `~/.dsh/.credentials.yaml` 里的 grant |
| 授权会话 | `dsh-authorization` | `registerFlow()` 抽象，**不决定登录按钮按下去做什么** |
| 账户 + RPC | `deepseek-account`（抽象）<br>`deepseek-account-platform`（实现）<br>`account-controller`（Web RPC，namespace `account`） | 提供 `deepseekAccount` 服务，暴露给前端 |

`AccountController` 的依赖是硬编码的：`static inject = ['deepseekAccount', 'agents']`。
这条依赖决定了 **`deepseek-account` 不能禁用**（坑 1）。

### 2.2 登录按钮的真实调用链

```
Desktop 欢迎页 → preload IPC → main.ts account.start(...)
  → POST /api/account/startSignIn → AccountController.startSignIn()
  → PlatformAccount.startSignIn()
  → authorization.begin({ key: 'deepseek-account-platform/default' })
  → OAuth flow 返回 authorizeUrl
```

Desktop 主进程拿到 `waiting-browser` + `authorizeUrl` 就打开浏览器（打开前校验：只能是
HTTPS 或 HTTP loopback），并在 `credential-stored + succeeded` 时自动进入工作区。

### 2.3 两个切入点

1. `startSignIn()` 返回自己的 loopback 地址 → Desktop 打开我们的登录页。
2. `getState()` 产出 `credential-stored + succeeded` → Desktop 自动进工作区。

这就是整个方案的全部原理：**替换两个方法的输出**，不碰 DSH 源码。

## 3. 方案

### 3.1 结构

```
deepseek-harness-login/
├── package.json          # dsh.bundle.patch + dsh.client
├── cordis.patch.yml      # insert 自己（不能为空）
├── lib/
│   ├── index.js          # Host：拦截 + 校验 + 写凭证 + 接管账户数据
│   ├── login-page.js     # 登录页 / 账户页（自包含 HTML）
│   └── client.js         # Client：隐藏平台入口
└── docs/
```

### 3.2 Host 端四件事

**① 注册本地页面路由**（用 Host 自带 webServer）：

```js
ctx.effect(() => webServer.register({ kind: 'exact', path: '/custom-login', handler: servePage }))
```

地址用 `webServer.getOrigin()`；若不是 loopback，替换成
`http://127.0.0.1:<port>`，否则 Desktop 会拒绝（坑 9）。

**② 替换 `startSignIn`**：不调原实现，直接构造 attempt 并唤醒 watch。

```js
account.startSignIn = async function () {
  attempt = { id: randomUUID(), phase: 'waiting-browser',
    authorizeUrl: base + '/custom-login?a=' + id, expiresAt: Date.now() + 10 * 60 * 1000 }
  account.changed()          // 不调用这个，Desktop 收不到新 attempt
  return account.getState()
}
```

**③ 包装 `getState`**：合并自己的 attempt，并把 links 换成本地账户页。

```js
account.getState = async function (...args) {
  const state = await rawGetState(...args)
  const links = local ? { usageUrl: base + ACCOUNT_PATH, topUpUrl: base + ACCOUNT_PATH } : state.links
  return { ...state, links, attempt: view }
}
```

**④ 提交时写凭证**：顺序不能反 —— 先置 `succeeded`，再写 record。

```js
attempt = { id: attempt.id, phase: 'succeeded' }
await credentials.modifyRecord(ACCOUNT_KEY, () => Promise.resolve(record))
```

写 record 会触发 `credentials/record-updated` → 账户 `changed()` → watch 推送。
如果此刻 `getState()` 还不是 `succeeded`，Desktop 就不会自动进工作区。

### 3.3 短路平台请求

本地 token 在真实平台必然 401，而 401 会触发 `expireCredential()` 删凭证（坑 5）。
所以自定义登录态下要接管这些方法：

| 方法 | 返回值 / 行为 | 原因 |
|---|---|---|
| `getProfile` | 本地账户名 + `contact` 副标题 | 不发请求；`contact` 为 null 会显示「账号资料暂不可用」 |
| `getBalance` | `{ status: 'ready', value: [], bonusWallets: [] }` | 返回 null 会被过滤成 undefined，界面永远「加载中」 |
| `getUnnotifiedBonuses` | `null` | 不发请求 |
| `ackBonusNotified` | `false` | 不发请求 |
| `rejectToken` | **空操作** | 这是删凭证的入口，必须屏蔽 |
| `getState().links` | 指向本地账户页 | 不再暴露 `platform.deepseek.com` |

### 3.4 Client 端：隐藏平台入口

设置页里硬编码的 `<a>` 无法通过 Host 返回值移除，用样式隐藏：

```css
[class*="accountInfo"] { display: none !important; }   /* 更多账号信息 */
[class*="balanceCard"] { display: none !important; }   /* 余额 / 赠金 / 查询用量 / 充值 */
```

依据：DSH 的 CSS Modules 产物保留 local 名（`AccountSection_accountInfo__hash`），
所以 `[class*="..."]` 稳定。与 `dsh-skin-techno-neon` 同一种做法。

### 3.5 加载页品牌

加载页由 `client/web` 的 `boot-page.ts` 在**插件加载之前**渲染，文案是硬编码的，
Client 插件来不及介入。因此从 Host 注入：监听 `webserver/index-inject`，
往 index.html 的 `<head>` 加一条 `style` 行（`lib/index.js` 的 `BOOT_BRAND_TEXT`），
把原文字 `font-size: 0` 后用 `::after` 显示「大伟的智能体」。

- 作用域 `[data-dsh-boot]`，只影响加载页，不影响主界面。
- 首屏第一帧就生效，不依赖脚本执行时序。

### 3.6 关键 API 速查

| 目标 | 用法 |
|---|---|
| 读 / 写凭证 | `credentials.readRecord(key)` / `credentials.modifyRecord(key, current => Promise.resolve(record))` |
| 拿 Host 地址 | `webServer.getOrigin()` / `webServer.port` |
| 注册路由 | `webServer.register({ kind: 'exact', path, handler })` |
| 唤醒账户监听 | `account.changed()`（TS private，运行时可用） |
| 账户状态 | `{ status, links, attempt }` |
| attempt 结构 | `{ id, phase, authorizeUrl?, expiresAt?, errorCode? }` |

`attempt.phase`：`initializing | waiting-browser | exchanging | committing | succeeded | cancelled | expired | failed`

## 4. 踩坑

### 4.1 五个关键坑

#### 坑 1：禁用 `deepseek-account` 会让 Desktop 起不来

现象：重启后弹 `Web authentication failed`，Web boot 里几十个 UI 插件卡在 loading。

根因：`AccountController.static inject = ['deepseekAccount', 'agents']`；Desktop 在 Host
就绪后立刻 `accountBackend.watch(...)`。禁用提供该服务的插件 → 账户 RPC 整体缺失。

结论：**不要禁用**。它不是"登录按钮"，是 Desktop 启动链路的一部分。

#### 坑 2：`cordis.patch.yml` 写成空数组，插件从未加载

现象：插件市场显示"已安装 / 正常"，但登录行为没有任何变化。

根因：DSH 的插件树是"从空列表开始、由各 bundle 的 patch 逐条构建"的。空数组等于
一行都没 insert，`apply()` 从未执行。

```yaml
- insert:
    - id: custom-login
      name: 'deepseek-harness-login'
```

验证方式只有一个：在 `apply()` 里打日志，确认真的执行。

#### 坑 5：登录成功后凭证被立刻删除

现象：登录成功，回到 DSH 却是未登录；`.credentials.yaml` 里没有对应的 grant。

根因：本地 token 是假的，进工作区后拉资料 / 余额收到 401，
`PlatformAccount.getDetail` 捕获后调用 `expireCredential()` 删记录。
**离线环境反而不触发**（连不上是网络错误，不是 401），所以只有有网时才撞到。

解决：按 3.3 短路那些方法，`rejectToken` 最关键。

#### 坑 13：用系统 pnpm 动 profile，会让插件市场装不上插件

现象：插件市场安装任何插件都失败：

```
[ERR_PNPM_UNEXPECTED_STORE] Unexpected store location
```

根因：DSH 内置 pnpm 11（`store\v11`），系统 pnpm 10（`store\v10`）。用系统 pnpm 在
profile 跑过一次 `install`，`node_modules/.modules.yaml` 就被写到 v10，之后 DSH
用自带 pnpm 安装插件时版本不匹配，直接拒绝。

解决：改用 DSH 自带 pnpm 重装 profile：

```powershell
cd "$env:USERPROFILE\.dsh\profiles\desktop"
node "<dsh-install-dir>\resources\runtime\primary-runtime\dependencies\pnpm\bin\pnpm.cjs" install --no-frozen-lockfile
```

> DSH 的 `resources\runtime\bin\node.cmd` 是 Electron shim，外部 shell 不可用；
> 直接用系统 Node（>= 20）跑 `pnpm.cjs` 即可。

#### 坑 14：重启后登录态丢失（issuer 被自己改坏）

现象：每次重开 DSH 都要重新登录，grant 整条消失。

根因：`PlatformAccount` 启动时校验 grant 的 `issuer`，与 `this.origin`
（`https://platform.deepseek.com`）不一致就 `deleteRecord()`。

而写入端当时从 `getState().links.usageUrl` 反推 issuer —— v0.4.2 为了隐藏平台入口
把 links 换成了本地地址，于是第二次登录写进去的 issuer 变成了
`http://127.0.0.1:<port>`，下次启动即被删除。

解决：issuer 直接取 `account.origin`，不再绕道 `getState`：

```js
function resolveIssuer(account) {
  const origin = account?.origin
  return typeof origin === 'string' && origin.length > 0 ? origin : 'https://platform.deepseek.com'
}
```

教训：patch 一个方法时，要排查所有**依赖它返回值**的内部逻辑。
`getState()` 同时被 UI 和写入路径消费，改 `links` 就改了 issuer 的来源。

### 4.2 其余坑速查

| 坑 | 现象 | 根因与对策 |
|---|---|---|
| 3 | 插件详情页红字 `failed to read overlay` | `dsh.bundle.patch` 声明的文件被删了。文件与声明必须一致，app-boot 是 fail loud |
| 4 | 注册了自己的 flow，登录仍跳 DeepSeek | 登录按钮只看 `startSignIn`，flow key 是硬编码的；抢同 key 抛 `DUPLICATE_FLOW`，禁用原插件又触发坑 1 |
| 6 | 余额一直「加载中…」 | `getBalance` 返回 null 会被 RPC 过滤成 undefined；返回 `{ status: 'ready', value: [], bonusWallets: [] }` |
| 7 | 副标题显示「账号资料暂不可用」 | 副标题取 `profile.contact`，返回 null 就落到兜底文案；返回字符串即可 |
| 8 | 账户名后面多出一串 UUID | token 用 `lastIndexOf('-')` 剥离，但 UUID 自带 4 个连字符。格式改为 `dsh-local-<base64url(user)>.<uuid>`，并保留旧格式正则兼容 |
| 9 | 打开登录页报 `invalid browser destination` | Desktop 只放行 HTTPS / HTTP loopback；构造 `authorizeUrl` 时强制 `http://127.0.0.1:<port>` |
| 10 | 完全移除插件后仍报 `Web authentication failed` | Electron cookie store 损坏，与插件无关。清理下面三处后恢复 |
| 11 | 提交回来 `attempt` 是字符串 `__ATTEMPT__` | 模板占位符忘 `.replace()`：`html.replace('"__ATTEMPT__"', JSON.stringify(String(attemptId)))` |
| 12 | 改了代码不生效 | patch / `package.json` / Host 代码要重启；`lib/client.js` 只需刷新页面 |
| 15 | 「应用 → 关于」菜单与弹窗改不了 | 属于 Electron 主进程，插件无注入点。详见 [品牌定制方案选型.md](品牌定制方案选型.md) |

坑 10 的清理步骤：

```powershell
# 1. Electron cookie / 网络状态（重命名备份后重建空目录）
$app = "$env:APPDATA\@deepseek-ai\dsh-desktop"
Rename-Item "$app\Network" "Network-bak-$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory "$app\Network" | Out-Null
# 2. Local Storage 同样重命名备份
# 3. 从 ~/.dsh/.credentials.yaml 删除 client-connection/browser-session 整块（下次启动会重新生成）
```

排查原则：先把"插件问题"和"环境状态问题"分开 —— 彻底移除插件后再复现一次。

## 5. 排错

```powershell
# 日志（登录、提交、写入、失败都有记录）
Get-Content "$env:USERPROFILE\.dsh\logs\deepseek-harness-login.log" -Tail 50
# 凭证文件
Get-Content "$env:USERPROFILE\.dsh\.credentials.yaml"
```

诊断端点：`http://127.0.0.1:<port>/custom-login/diag`，返回 `attempt` 阶段、
`lastError`、`store`（`"absent"` 表示凭证没写进去或已被删除）、当前 `state`。

| 现象 | 先查 |
|---|---|
| 点登录仍跳 `platform.deepseek.com` | 日志有没有「已拦截登录请求」；没有 = 插件没加载 |
| 登录页 404 | `webServer.register` 是否执行、端口是否一致 |
| 提交 409 | attempt 不匹配，多半重复点了登录 |
| 提交 500 | 看返回体错误 + 日志 stack |
| 登录成功又掉线 | `rejectToken` 短路是否生效、`store` 是否变 absent |

## 6. 已知限制

| 项 | 现状 | 建议 |
|---|---|---|
| 模型调用 | 仍指向 `api.deepseek.com`，假 token 必失败 | 配置内网 LLM provider（OpenAI 兼容） |
| 账户来源 | 硬编码在 `lib/index.js` | 对接后端鉴权接口 |
| 密码存储 | 明文常量 | 至少改哈希比对，正式环境走后端校验 |
| 登录页鉴权 | 仅靠随机 attempt id | 内网可信；要更严可加一次性 nonce + 过期 |
| 品牌 | 只能改 Web 侧 | 名称 / logo / 关于弹窗要改源码，见品牌文档 |

---

## 7. 一句话总结

> DSH 的登录不是"认证流程"，而是 **`deepseekAccount` 服务的两个方法**
> （`startSignIn` 与 `getState`）。替换这两个方法的输出，就能把整条登录与账户
> 展示链路换成自己的实现；而 `deepseek-account` 插件必须保留，它是 Desktop
> 启动链路的一部分。
